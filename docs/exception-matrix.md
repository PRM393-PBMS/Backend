# Ma trận exception PBMS

Phạm vi: backend NestJS/Prisma 6.4.1. Nguồn nghiệp vụ: [báo cáo kiểm tra ngày 02/11/2026](https://docs.google.com/document/d/1awRAfpITO0uUEhTHrxilWatcX587QJT-jOVHks0A7_k/edit). Frontend chưa nằm trong repository này.

## Hợp đồng lỗi

API PBMS giữ `statusCode`, `message`, `isSuccess`, `result`; lỗi có thêm `errorCode`, `requestId`, và `details` nếu cần. HTTP status phải bằng `statusCode`. Các lỗi nghiệp vụ cũ chưa có mã riêng dùng `HTTP_<status>`. Trường hợp bất ngờ dùng `INTERNAL_ERROR` và không công khai SQL, stack, token, OTP hoặc phản hồi nguyên gốc của nhà cung cấp.

Webhook thành công tiếp tục trả 200 body rỗng. Redirect, PDF và dữ liệu OCR thành công giữ định dạng riêng. Lỗi trước khi gửi file dùng envelope; lỗi stream sau khi đã gửi header đóng kết nối. Danh sách tải thành công nhưng không có bản ghi trả 200 với `[]`.

## Giới hạn xác minh

Các test PostgreSQL dùng `TEST_DATABASE_URL` riêng, bắt buộc host localhost/127.0.0.1 và tên database kết thúc `_test`. Không kiểm thử thu tiền thật, gửi OTP thật, mở barie thật hoặc gây sự cố Supabase. Test provider dùng mock và test HMAC độc lập. Cần smoke test với tài khoản sandbox của provider khi triển khai.

Unique partial indexes, check constraints và triggers được lưu bằng SQL migration; không được dùng `db push` hoặc tự động áp dụng output `migrate diff` để xóa chúng. Xem [runbook](exception-runbook.md) cho rollout, đối soát, và các lỗi ngoài phạm vi backend.
